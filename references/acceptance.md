# 集中验收、授权与发布

## 批次按风险和机制划分

| 类别 | 例子 | 推进方式 |
|---|---|---|
| 较低风险、可数据适配 | 已找到精确提供者的任务字段、追加掉落、资源引用修正 | 全量静态核对后组成一批；仍需对应行为抽查 |
| 持续兼容风险 | 对话/对战桥接、改变注册/组件的 fork、模型加载入口 | 按完整依赖链隔离、验证首因与本地回归 |
| 暂缓 | 无原生/低成本替代、缺提供者、需要大规模重写 | 说明缺什么、恢复条件；不为“全部完成”填空实现 |

不要每改一个文件要求用户进档；先把独立静态问题集中解决，固定候选清单，再安排一次覆盖多个机制的检查。已授权代理控制桌面时代理完成可执行部分；没有许可时准备简短集中操作单。新许可覆盖旧限制后继续，不让用户重复确认。

## 证据状态是多个字段，不是一串可以跳级的标签

每个功能/批次记录：准确输入与输出哈希、TEST/MAIN 路径角色、构建、静态、注册/菜单、世界加载、功能交互、保存重进、应用状态、残余问题。每份日志绑定实际 gameDir、玩家身份、时间与该次候选哈希。

| 证据 | 可报告 |
|---|---|
| 已生成且静态检查通过 | 候选已准备，真实启动未验证 |
| 菜单/postInit 通过 | 菜单与注册通过，世界/领奖/对战未验证 |
| TEST 交互且保存重进通过 | 指定 TEST、指定功能抽查通过，未覆盖部分列明 |
| MAIN 精确清单已应用、菜单通过 | 本批已安装，MAIN 菜单通过；不冒称 MAIN 世界已验证 |

用户可明确接受跳过某项后应用；把选择、剩余风险与实际验证写清，不伪造通过，也不无依据反复索取已有授权。对于已确认会损坏旧档的失败，先解决或隔离，不把它降格为普通“尚未验证”。

## 集中世界验收的最小闭环

用旧世界副本和原玩家身份，检查受本批影响的功能：新内容可获得→使用/触发→画面/任务/对战效果→原功能回归→保存退出→重进。涉及任务删除奖励、经济或数据迁移时另覆盖相关旧状态。新增数千皮肤时对获取、饰品、toggle、闪光、Mega 等不同机制抽样，不默认穷举每个外观；需要统计概率或完整覆盖时单独估算并确认工作范围。

快照还要包括原按键和资源包启用列表/顺序、旧选项及光影。Iris 等可能重写时间注释，区分文件哈希变化与有效配置变化。只比较键位行可能漏掉资源包禁用标记或新增默认快捷键冲突。贴图缺失先核对资源引用、版本及实际选择，不重置所有资源包。

## 应用与回退

先确认相关游戏进程正常退出；不要因为其它无关 Java 程序存在就默认杀掉它们。锁定清单含新增、替换、精确退役路径及预期旧/新哈希，包含支持链和额外旧脚本，不能只统计复制次数。读取型预览不是额外授权来源；应用权限来自用户请求和上下文。

应用前检查 MAIN 当前基线，漂移则重比对。替换/退役项备份；新增项记录原先不存在。涉及迁移时备份关联世界/玩家/地图/实体文件，不根据目录名猜关联，也不复制运行中正在写入的世界作为完整基线。复制后核对哈希和保留设置；分步失败要有操作日志和明确回退范围。

绝不把 TEST 存档、作弊道具或测试完成状态反向覆盖 MAIN。文件级回退与已经保存新注册 ID 后的存档回退不是同一件事；卸载已产生新道具的模组前重新备份并评估丢失风险。

交付单独保存简明当前状态、清单、复现步骤和证据索引，聊天历史不完整时可据此恢复。旧报告标记被哪个新状态替代，保留其原始证据；不让旧台账的“主实例未动”掩盖后续已经应用。

公开技能只携带通用说明、合成用例和有权发布的工具；不包含个人世界/UUID、主机绝对路径、启动令牌、作者 JAR、受限制资源或真实运行日志。公开仓库推送与游戏操作分别授权。
