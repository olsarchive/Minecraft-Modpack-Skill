# Cross-version completion and execution efficiency: lessons from 6.0.1

These are conditional mechanisms, not fixed versions, paths, or mandatory full-pack tests for every change.

## Avoid repeated handoffs

- Continue one authorized task to its concrete delivery boundary. Lock sources, the actual MAIN instance, dependency graph and ledger; batch independent offline work rather than asking separately for audit, staging, installation and readback.
- Unknown is not confirmed blocked. Resolve version syntax, Connector mappings and inherited methods before treating scanner warnings as hard conflicts. Fifteen purported missing methods were actually unresolved mappings.
- Check owner/name/descriptor and mapped inheritance. Constant-pool string presence alone proves neither compatibility nor absence. Prefer native releases; patch only confirmed, small API breaks. SpawnBucket removal requires an actual API adaptation, not a wider dependency range.
- Reuse unchanged evidence. Fix the first causal failure and retest affected chains, then sample the final locked combination. Avoid repeated full scans, downloads, world copies and unchanged legacy checks.

## Resource packs are active dependencies

- Inspect the author's enabled list, assets, consumers and effective providers. Copied is not enabled; required_data placement alone does not prove client assets are loaded.
- Preserve old entries and their relative order. Insert necessary new assets according to member conflicts, retaining local animation/fix priority unless specific updated resources must win. Do not enable every GUI, music or cosmetic pack.
- Deduplicate byte-identical aliases. An old JoStar 1.7 animation override caused 1.8 entity-sync parsing failures; update the active content when necessary while preserving its selection entry.
- Minecraft 1.21.1 uses client resource format 34 and data format 48. Check the client compatibility range separately. A necessary old-format acknowledgement is not rendering acceptance.
- Check affected resolvers, models, posers, textures and conditional animation coverage after reloading. Preserve shader and local texture fixes.
- Refresh options after game exit. Modify only authorized lists; independently compare old keybindings, other option lines, original pack bytes and effective shader settings. Do not copy TEST options wholesale to MAIN.

## Rewards and world migration

- Chat, event logs and Inventory.add success do not prove item delivery. Creative mode with a full inventory can discard the remaining stack while returning success. Test in survival with free slots and inspect actual items/containers.
- Separate native victory bags, species coins, opening/cooldown, redemption and equipping. A random miss is not failure; never increase probabilities or grant items as evidence of natural drops.
- Find all actual legacy item stacks before applying mappings. Use exact author coin_meta; do not approximate unmapped coins.
- Migrate only target fields in the current MAIN, preserving counts, unknown custom_data, unrelated components and other NBT. Verify non-target semantics and zero second-run changes. Never restore TEST player/container/world files over live progress.
- Remove only obsolete coin entries when the native event replaces them, preserving non-coin loot. Native rewards still need independent acceptance.

## MAIN, friend exports and cleanup

- Respect user acceptance of representative checks. Deliver the accepted scope and retain honest uncertainty; neither claim exhaustive stability nor keep every disposable clone indefinitely.
- Apply an incremental manifest, retire replaced active JARs, and exclude caches, probes, temporary quests and test progress. Transfer world patches by exact path, never by mirroring the world.
- Export a standard self-contained mrpack from synchronized MAIN, with mods, local adaptations, quests, scripts, resources, keybindings and shaders. Lock the exact loader. Friends import into a new instance rather than overlaying old mods.
- Exclude accounts/tokens, private worlds, inventories/Pokémon progress, map trails, client encounter databases, logs and temporary probes. Verify every archive member and settings; friend-machine runtime remains a separate result.
- Before cleanup, verify the MAIN manifest, process ownership and unique progress. Keep a necessary short-term rollback and concise evidence. Use supported launcher removal, never manual database edits; report any real removal blocker.
- Delete only resolved absolute targets within verified boundaries, rejecting junction/symlink escapes and using one shell throughout. Report reclaimed disk bytes, not RAM.
