# 兼容性和历史失败判读

## 版本与身份

同版本不等于同内容。取官方 index 哈希或实际 JAR 哈希作为身份，保留文件名版本与内部版本两个字段。有些模组内部版本长期是 `1.0-SNAPSHOT`，有些是 `${file.jarVersion}`，应核对 Manifest，不能据此排序版本。

NeoForge 的 `META-INF/jarjar/metadata.json` 和 Fabric 的 `jars` 声明包含内嵌模组/库。Connector、KotlinForForge、Create 等不一定能靠根部 mods.toml 完整识别。内嵌同 ID 可能由加载器选择一份，不能直接定为重复故障；先结合版本选择范围与实际启动日志。

同 MC/loader 的公开版本仅是候选。不要自动取最高版本：作者精确锁定某版本、或本地保留的功能要求旧 API 时，较新版本可能不匹配。

作者自制模组还需查看精确依赖、Mixin 目标和实际功能入口。例如任务奖励引用新的物品命名空间，则只搬任务会造成空图标、无法领奖或无法完成。

部分作者兼容模块按依赖 JAR 的精确哈希决定是否启用；原生替代版即使版本相同，也可能被有意跳过。记录哪些功能实际进入了执行路径，不能伪造哈希或去掉保护来宣称同步成功。

旧移植可能改过物品命名空间。升级前比较真实注册入口，针对旧 ID 的原生映射须先验证加载阶段、完整目标集、重复执行和冲突处理，再在旧档中验证背包、携带物及保存重进。模拟注册表测试只能证明补丁逻辑，不能证明游戏兼容。正式原生版本已提供相同修复时，退役依赖旧 Java 类的脚本，记录旧文件哈希及恢复方式。

## 三方合并的局限

脚本的 `unknown_baseline_conflict` 意味着旧版该路径没有文件，不能推断 L 是错误文件。改名和跨加载器替换必须用模组身份建立映射后再决策。

ZIP 成员哈希比较可以识别压缩方式或时间戳造成的假更新；它不等于 JSON/脚本语义验证。两个内容不同的包也可能在当前加载顺序下无效，必须继续核对提供者。

作者从一个包删除数据，可能将相同功能迁入另一个包或 JAR。先找新提供者再处理旧提供者；只做并集会把有意删除的旧规则重新启用。

多祖先整合包按内容归属使用各自基线：作者旧内容、移植基座、本地新增、人工改版、来源不明。不要根据同名路径自动把较旧基座覆盖回去。

## 失败记录是条件化证据

每条记录至少包含：目标文件哈希/版本、MC/loader、关联依赖、世界/数据快照标识、具体触发动作、最早因果异常、修法或撤回、验证级别。

| 已观察到的失败类型 | 下次该做什么 |
|---|---|
| 为匹配参考包降级 Create，其他附属依赖较新 Create | 求整条已安装依赖链交集，不能只满足被复制的参考包 |
| 只改不兼容声明后“可以加载” | 检查实际 API/字段/方法描述符与运行行为；元数据通过不是修复 |
| 字段名称相同，类型从 BooleanValue 变 Supplier | 按完整 JVM 描述符核对二进制兼容；不要再改配置或反复加同名字段 |
| Sheets 过早初始化、模型层未注册 | 定位注册阶段和客户端映射，不把移除渲染内容称作完整适配 |
| 主菜单正常，进旧世界才触发地牢清理/区域删除 | 停止升级链，保留源世界；验证迁移方案后才重新试 |
| 新版库与旧数据包 JSON 不兼容 | 连同脚本、数据格式和注册表修正；不能删平衡包掩盖问题 |
| 覆盖原版 JAR 导致已修问题复现 | 查本地哈希与补丁账本；保留、重建或由正式上游修复替代 |
| 错误账号进入世界后背包为空 | 核对 UUID/玩家存档绑定；不通过改主世界玩家身份来制造测试通过 |
| 资源包都在，但启用顺序丢失 | 比较 options.txt 和全局加载入口，保留用户视觉与键位选择 |
| 只复制船体索引，关联的实体数据缺失 | 世界迁移按关联文件成组快照，例如船体索引与船体数据；不能单独恢复索引制造完整假象 |

本次发现的历史台账如果与当前依赖版本不同，只能用于提出回归用例。例如旧 Iris 阻塞新 Sodium 的结论，在 Iris 已升级后不能继续当成当前事实。目标版本未改、旧档仍在、还没拿到迁移证据的删除/丢数据记录，继续阻止主包应用。

## 数据包实际入口

检查 globalpacks 配置的 required/optional 路径，资源目录是否同时作为数据目录、是否存在专门 override 路径；不要靠文件名前缀猜顺序。

世界内包常使用 `file/<name>` 标识，全局/内建包标识可能不同。以当前加载器报告与世界启用列表为准，不能凭猜测同时写两个名字。检查 `Missing data pack` 是否来自**本次**启动。

同一包同时出现在资源目录、全局数据目录、世界目录时，比较哈希、有效数据内容、实际优先级与本地修改。不要为了“保险”复制出更多版本。货币问题分别验证机器消耗标签、商店/银行配置、配方及任务文字，避免只修文本。

## 调试收敛

一次只改变一条已证明有关的依赖链，测试失败从该链基线恢复，记录首个根因而非最后级联报错。不延续移除检查、空实现、广域 catch、强行启用所有资源或随意重置配置的尝试。

代码补丁优先窄而可构建：明确源/目标哈希、修改的类/描述符、断言与测试。能由官方同功能版本解决时不用自制字节码补丁。上游已经修复后删除该次补丁需验证等价行为，不能只看版本号。

审查三轮各有目的：① 内容覆盖及本地保留；② 依赖、实际入口和失败路径；③ 去掉重复/失效步骤并复核回滚及产物。不要把逐个碰错后连续发布的 v1/v2/v3 当成稳定流程。
