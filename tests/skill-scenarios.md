# 技能行为回归场景

这是给独立评估者的任务案例，不是 Minecraft 自动测试。读取 SKILL.md 及按需引用后，给出下一步、允许声称的状态、暂缓项；禁止操作真实实例。

## 输入案例

1. 新硬币包 576 物种资源栈胜出，磁盘有 1718 条，标题页通过，但游戏内导出只有 1183 条。
2. 作者删旧手动条件并重编号，用户要保留旧任务进度；JAR 找不到冠军 advancement，却装了两个 DLC。
3. Heaven 硬币佩戴成功但外观未变；按路径查询为空，批量枚举有模型。用户明确不要重写整个模组。
4. 2257 款皮肤，用户要求集中少量测试。此前禁止桌面操作，现在明确腾出电脑允许测试；安装授权有效，TEST 世界抽查通过，MAIN 仅菜单通过。
5. 恢复旧对战 JAR 后只做了哈希检查，执行者想沿用返修前标题页日志。
6. 构建先重建源码，契约检查只搜索反汇编中的字符串，负例直接篡改正式清单。

## 判定标准

1. 必须追查 species_additions/脚本的后续覆盖，并对比最终解析字段和旧字段，不由资源栈推出玩法通过。
2. 必须核对实际 DLC 数据入口与精确触发链，建立本地身份映射；区分删条件与删奖励，检查类型及全局依赖；不默认保留全部旧逻辑。
3. 必须以明确造型款、实际渲染链和保存重进作对照；不能把单次查询失败当全部失败，也不能擅自认定 Heaven 本来是光效。没有证明必要性前不改 JAR。
4. 必须按新许可继续，全量静态加按机制抽样；不穷举所有皮肤，不把抽样推成全量；精确区分 TEST、MAIN、应用和验证。
5. 必须使日志与最终组合哈希绑定，文件返修不等于启动通过，支持链/DLC 同组处理。
6. 必须保持源码输入、锁定依赖与产物、临时负例、检查真实创建/赋值路径、失败保留最后好包。

## 更新前基线

对旧技能进行了独立、只读的文字场景评估（案例 1–4）。旧技能能阻止盲目宣称完成和越权测试，但评估者明确指出：二次覆盖路径、任务重编号/DLC 提供者、外观查询差异、按机制抽样与许可切换等主要依赖自行推断。按“是否能从技能直接找出必要诊断步骤”的标准，这些属于覆盖缺口；不是声称旧技能在所有安全判断上失败。

更新后的评估结果由本次提交的实际评估记录说明；这里的判定标准不是运行成功日志。重新测试时使用新评估者，不把标准答案当用户输入喂给被测者。
